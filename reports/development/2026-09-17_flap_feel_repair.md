# 為什麼那個蓋子不像紙箱：四個量出來的原因與修正

使用者回報四件事：關著時怎麼拉都拉不開、拉開後怎麼用力都不會留下摺痕、放手就強力彈回、板面一條一條彈開。
新增純離線模組 [carton_feel.py](../../src/parcel_forge/carton_feel.py)，把 config 換算成手能感覺到的量。
在使用者當時載入的資產 [20260917T123830Z](../../runs/20260917T123830Z_ext1_independent_interaction/config.json)（MajorYN）量到：

| 量 | 舊值 | 意思 |
| --- | --- | --- |
| 摺痕降伏角 Y/k | 42.97° | 拉過 43° 之前完全不會產生永久摺痕，摺完的回彈量也是 43° |
| 塑性速率上限 | 0.123 rad/s | 且**只取決於角度**，角度又被 100° 限位夾住，所以拉多用力都一樣 |
| 摺 45° 所需持續時間 | 6.40 s | 必須「拉住」六秒，快拉一下等於沒拉 |
| 殘餘力矩 / 蓋子自重力矩 | 5.35 | 摺過之後硬挺挺立著，永遠不會自然垂下 |
| 分段板 omega·dt | 24.9 | 可積分上限約 0.3，勁度超出 6900 倍，PhysX 只能讓條狀片抖動亂彈 |

尖端只要 0.30 N 就能把關著的主蓋拉到 90°，所以「拉不開」不是硬度，較可能是那個不可積分的分段板讓整個
articulation 在抖。

## 修正

1. **塑性改成率無關。** `crease_model.advance` 現在允許黏度為 0，那正是它的 backward Euler 形式本來就內含的
   return map：`delta = (|M|-Y)/k`。拉得越用力，同一個 step 摺得越多，不必拉住六秒。
2. **摺痕參數不再用手填。** `derive_carton_creases` 從兩件真實紙箱可觀察的事反推：摺過後**回彈幾度**，
   以及**摺過的蓋子撐不撐得住自己的重量**。勁度與降伏力矩依摺痕長度縮放，所以四片蓋回彈角一致、
   各自承受同樣倍數的自重。目標值 4° 與 1.5 倍自重是假設，標為 `uncalibrated_assumption`。
3. **互動資產改剛性板。** 這塊板的彎曲勁度是它自己摺痕的 530 倍，切成條在這個 timestep 根本不可積分。
   所有柔度集中在摺痕，板面保持平的——這才是紙箱的行為。
4. **不可積分的板不能再被悄悄產生。** `author_segmented_carton` 預設拒絕；兩個要重現舊證據的 legacy 模組
   明確傳 `panel_stability_policy='record'`，而且會把不穩定數據寫進 config。

## 仍然不能宣稱的事

真實紙板校正 not_tested，上面 0.16 N／0.30 N 是這個模型的預測，不是量過真紙箱得到的。
拿廚房秤與量角器照 [校正協定](../research/CARTON_CALIBRATION_PROTOCOL.md) 量一片真蓋，就能檢驗或推翻它。
箱壁與底仍是剛體，沒有殼變形、壓皺或撕裂。MD/CD 板面異向性目前不在互動資產裡（分段模型仍在，但不可積分，
要用必須降低勁度或加大 dt 並重新驗證）。原生 WebRTC 滑鼠拖曳、render、影片與人眼確認本輪都沒有執行。
