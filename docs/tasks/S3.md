# Task S3: Parameterisation and static validation
Status: done (verified)
Depends on: S2 verified (normal box passes, both fault cases fail for the right reason)

Handbook sections: 6 (tool contract), 7 (schema), 10 G1 (static USD checks).

## Goal
A written specification file drives the generator end to end: an illegal spec is
rejected **before** the simulator starts, a legal spec produces a USD asset whose
dimensions are correct when read back **from the output**, and ten cases run as a
set with hashes linking input to output.

## Scope
- `src/parcel_forge/schema.py` — load and validate a case file: units, enums,
  finite numbers, mass > 0, constructible dimensions, unique names, and
  **unknown fields rejected**. Type checking alone is not enough. No simulator import.
- `src/parcel_forge/usd_author.py` — author a clean asset layer (the S2 export
  currently carries Kit's `/Render` scope; S3 writes the asset on its own stage
  with `defaultPrim`, `metersPerUnit=1`, `kilogramsPerUnit=1`, `upAxis=Z`).
- `src/parcel_forge/validation/static_usd.py` — reopen the written file and check:
  opens without missing references, defaultPrim set, units and up-axis, world
  dimensions per plate, plate count, Collision/RigidBody hierarchy, finite mass
  and inertia. Geometry tolerance 0.0001 m, read from output geometry and
  transforms only — never by comparing the input spec against itself.
- `scripts/pf build` and `scripts/pf validate` replace their exit-4 stubs.
- 10 cases in `cases/`: legal variants (sizes, thicknesses) plus illegal ones
  (L <= 2t, non-finite, negative mass, unknown field, bad enum). Each illegal case
  names the error class it must produce.

## Acceptance
- Every illegal case is rejected by `pf build` with exit code 2 and a named error
  class, with no simulator launch in its log.
- Every legal case produces a USD file whose read-back dimensions match the spec
  within 0.0001 m, and whose `validation.json` lists each rule with pass/fail.
- Each run manifest carries input hash, asset hash, validator version and profile
  version, so a result can be traced back to the exact bytes that produced it.
- Anything the official Isaac Sim asset-validation rule set cannot run is reported
  `blocked`, never silently skipped, and skipped rules are listed with rule IDs.

## Failure routing
Dimension mismatch -> check for a double scale on an ancestor before touching the
tolerance. Missing defaultPrim or wrong units -> fix the author step, not the checker.

## User learning
Concept: a schema rejects bad input early and cheaply; a static validator checks the
*output file* the simulator will actually load. They catch different mistakes.
Experiment: add `"colour": "brown"` (a field the schema does not know) to a case file
and run `pf build`. It must be rejected as an unknown field, not silently ignored —
silent acceptance of typos is how a spec quietly stops meaning what you think.

## Result (2026-09-16)

Commands: `./scripts/pf verify --all` -> exit 0 in 4.2 s (13 cases, no GPU, Kit never started);
`./scripts/pf box --all` -> exit 0 (6 legal cases simulated).
Suite tables: `runs/20260916T064613Z_s3_verify_bad_wall_too_thick_suite.md`,
`runs/20260916T064747Z_s2_open_box_thick_wall_suite.md`.

### 6 legal cases: built, statically validated, and simulated
normal, sealed, no_bottom, small (0.15x0.10x0.08, t=3mm), tall (0.20x0.20x0.30),
thick_wall (t=20mm). Every one passed all 10 graded G1 rules, and every one
produced the physics outcome its case file expected. The thick-wall case landed at
box-local z = 0.040000 m, exactly t + probe/2 = 0.02 + 0.02.

### 7 invalid cases: each rejected for its declared reason, before any launch
| case | error class |
| --- | --- |
| bad_wall_too_thick | geometry_not_constructible |
| bad_probe_too_big | geometry_not_constructible |
| bad_unknown_field | unknown_field |
| bad_negative_probe_mass | value_out_of_range |
| bad_fault_enum | enum_invalid |
| bad_non_finite_height | value_not_finite |
| bad_units_cm | unit_mismatch |

### Not delivered here
`pf validate` exists as part of `pf verify` rather than as a standalone asset entry
point. Isaac Sim's official asset-validation rule set is still not invoked: every
validation.json reports `G1.official_isaac_asset_validation` as **blocked**, and the
report states in writing that passing these rules is not a SimReady certification.
