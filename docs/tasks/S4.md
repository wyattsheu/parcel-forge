## Physical-parameter honesty (from Scalable Real2Sim, see docs/METHODS.md)

Published identification accuracy, with real torque sensors: mass 1.34%, COM 2.15%,
**rotational inertia 42.35% +/- 15.64%** (one object 358.6%). Inertia is the least
trustworthy quantity in any such pipeline. Therefore:

- Every physical parameter carries a confidence tier in its provenance:
  `derived_exact` (closed-form over a known shape), `estimated` (assumed), or
  `measured` (nothing in this project qualifies; no run may claim it).
- The PhysX read-back tolerance for inertia is explicitly looser than for mass, and
  the number is recorded rather than rounded away.
- The report must state that agreeing with our own formula is **not** evidence about
  a real cardboard box. It only proves the tensor we authored is the tensor PhysX got.
- **Pseudo-inertia feasibility check (adopted directly):** the inertia tensor must be
  positive definite and satisfy the triangle inequalities
  (Ixx + Iyy >= Izz, Iyy + Izz >= Ixx, Izz + Ixx >= Iyy). No rigid body can have a
  tensor that violates these, so an authored tensor that does is a build error, not a
  tolerance question. Cheap, deterministic, and it belongs in `mass_properties.py`.

## Failure routing
Inertia mismatch -> check the density basis (plate volume vs envelope) before
touching PhysX. Probe passing through a wall -> check contact offset and collider
presence; never disable collision or widen the tolerance. Box coming apart ->
check that only the root has a rigid body.

## User learning
Concept: mass is how hard something is to push; the inertia tensor is how hard it
is to *spin*, and it depends on where the material sits, not just how much there is.
An empty box is light but not easy to spin, because its mass is all at the edges.
Experiment: in `mass_properties`, change only the shell mass from 0.20 kg to 0.40 kg
and predict the COM (unchanged: 0.0552 m, because the distribution is unchanged) and
Izz (doubled, because inertia is linear in mass).
