# 以機器人任務驅動的物理資產工作流：改進計畫

> 後續實作以 [完整主計畫](2026-09-18_general_asset_workflow_master_plan.md) 為準；本文件保留問題分析與來源。

狀態：proposal，僅規劃；未實作以下新流程、未重跑物理、未宣告材料已校準。
日期：2026-09-18 Asia/Taipei。沿用 parcel-forge、既有官方 adapter 與檔案式 reports，不另建服務、資料庫或回報平台。

## 1. 要解決的問題

目標是減少「做出來才發現不能用」的對話，而非保證任何物體一句話就能得到真實材料模型。
必要參數取決於機器人任務、載荷與所需精度；只查詢物體名稱無法確定全部必要參數。
預處理必須同時產生：需求、參數來源、模型能力邊界、驗收測試，以及可互動的交付規格。

所有資產預設是被動物件：由接觸力、外力、重力、碰撞、材料定律決定運動。
不使用 open/close 狀態機、播放角度曲線、直接改 pose 或位置伺服來冒充開箱。
材料內部狀態更新（例如塑性參考角、損傷）可以需要程式；它必須回應受力歷史，不能代替機器人施力。
測試夾具可以有受控運動，但要與資產分開；通過外力測試不代表機器人抓取或原生滑鼠已通過。

## 2. 依據與現況

本計畫核對使用者提供的兩份對話紀錄，以及 STATE、ROADMAP、ENVIRONMENT、EXT1/EXT2、D060–D068、現有匯出包。
對話中的「計畫」「AI 宣稱成功」「真正命令證據」「使用者確認」分開處理，不把歷史說法全部當成實測。

- 紙箱最新交付為 exports/carton_v1，來源 20260917T150447Z_ext1_carton_pull；自由箱體、四片剛性蓋、摺痕 callback。
- 最新紀錄是可翻至 270°，不沿用早期 100°／179°限位。角度依座標定義，不能當成所有紙箱的標準。
- 原生拖曳已有使用者確認；本次沒有再觀看 WebRTC。先前拖曳障礙是歷史回歸案例。
- MD/CD 板面變形、凹陷、壓潰、撕裂不在目前剛板資產能力內。材料仍未實物校準。
- 泡泡紙紀錄曾採 Isaac 5.1；本專案為 6.0.1。不可直接搬用其 API、參數單位或成功宣稱。
- 現有 EXT2 已規劃 intended_task 選測試；本案延伸該方向，並提前至生成前確認測試覆蓋。

## 4. 完整流程與各階段輸出

| 階段 | 工作 | 輸出／離開條件 |
| --- | --- | --- |
| A 任務預處理 | 辨識物件、機器人動作、初態、內容物、固定方式與所需行為 | task_brief；重要歧義一次集中詢問 |
| B 查證與需求補全 | 查產品資料／標準／論文，拆解部件與接觸界面，列來源和未知量 | parameter_cards + missing_requirements |
| C 能力確認 | 對照本機版本，驗證選定模型能支援所需力學與 reset | capability_report；不支援則 blocked 或明示提案 |
| D 凍結規格與驗收 | 鎖定單位、材料、能力、測試、容差、交付方式 | asset_contract + validation_plan 版本與 hash |
| E 生成 | 官方工具負責其支援的幾何／材料／USD 作業，自訂後端負責特殊物理 | asset + runtime；保留生成器／prompt／版本 |
| F 分層測試與修復 | 先便宜檢查再物理；按失敗分類，限制修復範圍 | 原始證據、逐項 verdict、修復鏈 |
| G WebRTC 與交付 | 真正匯出包冷載入、受力互動、人工小實驗 | live loader、操作卡、限制與人工確認 |
| H 知識回存 | 將新失敗變成回歸，將有效來源／測試配方快取 | 可重用零件／材料／測試配方與版本 |

預处理不是每個物體問一份數十題問卷。先問 3–5 個真正影響模型的問題，其餘由來源推導或標記估計。
例如「生成紙箱」先問：只開蓋還要壓凹／撕破？膠帶已拆嗎？空箱或有內容物？箱體可自由移動嗎？有尺寸／型號或可接受範圍嗎？
不要求使用者懂塑性模數；系統將「小力會回彈、折深後留下摺痕」轉成可量測曲線與待校準項。
需求不明且影響成功定義時必須確認；低風險外觀細節可以清楚列預設，不能以沒有回覆當成批准改變任務。

## 5. 參數與網路查證規則

每個關鍵參數需有 value/range、unit、來源 URL/頁碼、取得日期、材料型號、測試條件、confidence、provenance、使用在哪個模型與測試。
provenance 至少分 user_given、measured、manufacturer、literature_matched、literature_analogy、derived、assumed、unknown。
衍生值保留公式與輸入來源；信心低就安排敏感度測試，而不是自動補成「標準值」。

來源順序優先實際材料量測／同型號廠商資料，其次符合材料與條件的研究；標準提供量測方法，不一定提供材料常數。
記錄濕度、方向 MD/CD、厚度、試片宽度、載荷速率、循環次數。鋼板上的膠帶剝離數值不可直接宣稱適用 PE。
無實物時交付「文獻／假設範圍內的模型」，不能宣稱真實紙箱觸感已驗證。參數隨機化也不能代替校準；相關參數須一致，避免不可能的質量／厚度組合。
來源快取需附適用條件與版本；新物體名稱相同不代表可以沿用同一材料值。

## 6. 泛化方法：組合物理行為與測試

物件名稱選幾何生成器，intended_task 選任務測試，required_behaviors 選材料能力與測試。
部件和界面獨立建模，例如紙箱＝板面＋摺痕＋接觸；包杯＝杯體＋膜＋重疊層＋膠帶＋緩衝接觸。
先重用已驗證的行為配方；遇到新機制先做最小能力實驗，不直接自動產生整套複雜資產。

| 測試層 | 共通內容 | 紙箱 | 泡泡紙包杯 |
| --- | --- | --- | --- |
| 通用結構 | USD、單位、尺度、質量／慣量可行性、資產引用、碰撞 | 四蓋與關節軸、限位幾何 | 杯口／把手可達、膜重疊、接合位置 |
| 材料與元件 | 解析解／獨立參考、參數讀回、加載卸載 | 摺痕力矩–角度、回彈、循環；需要板彎曲才增加 MD/CD | 拉伸、彎曲、壓縮、摩擦、膠帶剝離／剪切 |
| 任務裝配 | 受力接觸、可達性、成功及合理失敗 | 四蓋分別受力、自然阻擋、開後壓回、自由箱體平移 | 夾持不漏杯、接縫可釋放、解包後可取杯 |
| 數值穩健 | dt／網格／solver 敏感度、重複 run、接觸／能量異常 | 完整箱體不能只以板條試片代驗 | 質量比、初始張力、層間穿透、暖機後重載 |
| 執行與交付 | 冷載入、reset、保存／恢復、callback 數量 | 塑性角歷史保留／重設語義 | 斷鍵、膜 rest shape、速度與應力狀態 |
| 人工觀看 | 真 live、操作者輸入有效、操作卡 | 拖單蓋、放手、折回 | 壓膜、拉接縫、移開膜；缺能力就明示未支援 |

測試配方包含 fixture、施力方式、觀測量、參考來源、容差理由、preconditions、適用模型、成本及 pass/fail/blocked/not_tested。
未知 required check 必須拒絕；未支援的必要能力不能 skip 後總結 pass。
容差在生成前訂好。可以修正有證據的測試 bug，但需獨立審查、版本化與舊結果保留，不讓生成器改自己的分數。
負向測試必須包含：錯單位、錯質量、缺 runtime、缺膠帶釋放能力、視覺網格不跟隨、檢查未執行。
剛板不能以寫入 MD/CD metadata 宣稱支援板面彎曲；薄膜不能以 4 mm 碰撞外殼宣稱支援氣泡壓縮。
有限步未發散只證明當次數值狀態，不證明長期穩定或實物一致。

## 7. 官方工作流保留在哪裡

保留 config/upstream_content_agents.json 的固定 commit：a96faf9cb2f5c1f655fe0d60c0ccf57e3477b1aa。
沿用已有 prepare/check/finalize adapter、資產檢查及證據鏈；不為預處理重寫官方 repo。
自訂層補在前後：任務需求與物理能力約束 → 官方／自訂生成 → 通用檢查＋任務／材料檢查 → live 交付。
官方 README 描述內容工作流，不提供任意材料真實性認證；41 條資產規則通過不等於紙箱或包材物理已校準。
網頁新版與本機 pinned 版本分開記錄；不照新版安裝指令更動共享環境。

修復最多三次為建議預算，需檢查既有 repair guard 的實際契約後沿用。
每次綁 source_run、spec/profile hash、attempt、允許變更路徑；禁止縮小 probe、關閉必要碰撞、改驗收門檻、刪掉必要行為。
失敗分成需求矛盾、模型不支援、數值、生成 bug、驗證 bug、載入／UI、外部服務；不能全部丟回生成器重做。
材料模型改選若改變可支援行為，須回 D 階段另開規格版本；critic 不能將失敗升級為通過。

## 8. WebRTC 交付契約

每件資產必須附 live loader、已測命令、版本／依賴、來源 run/hash、能力限制、三個小實驗及預期結果。
介面可提供 Play、Reset、相機與診斷；不提供開／關按鈕代替物件物理。自動施力工具是測試夾具，不冒充滑鼠驗證。
重用既有 viewer，不重啟或停止使用者程序，不佔用其埠。GUI 必要 extension 缺少時報 blocked，不私改共享設定。
載入時顯示資產 ID、模型種類、runtime 是否啟用；檢查 callback 不重複、停止後不殘留、換資產不引用舊 stage。

小實驗規格：
1. 紙箱：抓大蓋外緣，小幅拉後放手；只改拉動幅度，再比較較大變形後的殘留角。角度是觀察量，不是控制指令。
2. 包材：同一位置、同一施力方式，只增加壓入程度，觀察軟層到硬杯的反應；模型不支援壓縮就不得交付這個宣稱。
3. 解包：只改膠帶是否已透過力學失效，確認接縫從受約束變成可分離；不能靠按鈕刪 attachment。

每次交付分列 physics_execution、state_readback、headless、render、human_webrtc；人工確認前最後一項必須 not_tested。
短片只在重要里程碑／修復前後有價值時，以背景工作產生，保存 request/status/result；不每次測試都渲染。
影片不能代替 live 互動或材料校準。runtime 必需時一併交付 USD＋程式＋參數，不再只給 recording.usda。
將匯出包移到新目錄後測試，不依賴原 runs 絕對路徑；單 USD 的退化行為須清楚說明。

目前已有 carton_v1 載入器，但它使用 __file__，不能單純貼檔案內容就假設 Script Editor 有該變數。
後續交付 gate 要以真實 Script Editor 入口實测，包括重複執行時保留並關閉上一個 controller；這次不提供未測的新啟動器冒充完成。

## 9. 分階段實作順序（待開始，逐卡完成）

| 順序 | 有界工作 | 完成條件 |
| --- | --- | --- |
| P0 需求契約與失敗案例 | 兩個物件的 task_brief/contract/能力缺口；統一最新文件 | 每個歷史重大問題都有對應 requirement/check；需求刪減可被拒絕 |
| P1 預處理與来源卡 | 自然語言拆解、來源檢索快取、一次集中確認、未確定項分類 | 「紙箱」與「包杯」自動列不同的能力／必要參數，無來源不冒充實測 |
| P2 EXT2 測試選擇 | registry＋task/behavior 對應，先接既有測試；不在本卡做 deformable | 舊 verdict 不變；缺必測項硬失敗；第二幾何家族重用同任務檢查 |
| P3 能力探針與生成串接 | 在本機 6.0.1 驗證所需元件，選適合模型；接官方 adapter | 必要能力有證據才生成；不支援不偷偷換成外觀代理 |
| P4 live 交付與修復 | 冷載入、生命週期、被動互動、背景影片、bounded repair | 使用者能按操作卡重現；headless 和 WebRTC 分開記錄 |
| P5 比較與泛化 | 固定版本／模型／預算，舊流程對照新流程，新增保留案例 | 比較澄清輪次、修復次數、首輪通過率、總時間／成本、錯誤通過與缺測率 |

P0 是下一張要完成的工作，不一次啟動所有 P0–P5。特殊板材破壞與泡泡壓縮另外開能力卡，不夾在 registry 重構裡。
P2 的跨幾何共用檢查不得偷用紙箱 AABB 代替杯口／內腔幾何；共用觀測介面、各生成器提供實際碰撞／容積查詢。
P5 先用紙箱、包杯作歷史回歸，再選未調參的第三物件作保留案例。來源與要求相同才比較，不能靠少驗項目提高通過率。
首輪通過率定義：在需求確認後，首次生成即通過所有必要機器測試；人工 gate、校準 gate 分別計數。
先量現有基線，再設定改善目標；本計畫不承諾未量測的效率提升百分比。

## 10. 記錄與報告

沿用 reports/development/：記錄工作流建置到哪一階段、實作內容、證據、下一步。
執行個案各用 runs/<id>/ 保存 brief、來源卡、contract、validation plan、USD/runtime、結果及修復鏈；運行進度報告放 reports/ 下既有執行報告位置。
兩種進度分開：工作流 P0 完成不代表某物體物理成功；某物體生成成功不代表整套流程完成。
不另建網站、服務、資料庫。CLI 名稱等到實作卡確定後才加入，不在規劃裡寫不存在的命令讓使用者執行。

## 11. 參考來源與使用界線

- [NVIDIA usd-content-agents](https://github.com/NVIDIA-Omniverse/usd-content-agents)：官方工作流能力；實作以本機 pinned commit 為準，不把主分支更新當成本機已安裝。

- [ISO 5628:2019](https://committee.iso.org/standard/76347.html?browse=ics)：紙／紙板彎曲測法，瓦楞板建議四點法；不能拿板面剛性測試代替摺痕遲滯校準。
- [ASTM D1596-14(2023)](https://store.astm.org/d1596-14r23.html)：包材動態緩衝測法；材料試片的結果不自動等同整個包裝。壓縮／緩衝能力不可僅由可見泡泡推定。
- 本地 docs/research/CARTON_CALIBRATION_PROTOCOL.md、CARTON_MATERIAL_SOURCES.md、CARDBOARD_MECHANICS.md：既有材料研究入口；逐項確認材料與條件適用性後才採用數值。
